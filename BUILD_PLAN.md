## Product summary

- Study scriptures across religions: Christianity, Judaism, Islam, Hinduism, Yoga, Buddhism (more later).
- Base language: English. Translation languages: Spanish, French, Italian, Portuguese, German, Russian, Latin, Greek, Arabic, Hebrew.
- Show the selected text with any number of languages side by side (Column view) or one under another per verse (Stacked/Parallel view).
- For each language the user can show:
  1. **Native** — that language's own published translation (e.g., Spanish = Reina-Valera 1909), and/or
  2. **AI** — the English text translated into that language by AI, clearly labeled "AI translation".
  Both must be available **at the same time** (e.g., RVR 1909 column next to "English → Spanish (AI)" column). Default for each language = Native when one exists for that text; fall back to AI when not.
- Highlight, bookmark/save verses, write notes.
- "Ask AI" about any verse — for now via an "Ask in…" hand-off to Gemini / ChatGPT / Claude (see Study features); a built-in Ask AI panel is designed but hidden behind a feature flag for a future paid tier.
- Free product for now (decided 2026-11-03), with the source code in a **public** GitHub repo (sknapp1991/snoopwiggy). Keep the architecture production-ready in case a paid tier comes later. Licensed (copyrighted) texts must never be committed to the public repo. If one is ever added, serve it at runtime from the publisher's API or private storage.

## Tech stack

- **Next.js (App Router) + TypeScript + Tailwind CSS.** Pin dependency versions.
- **Server-side API routes for all AI calls.** The API key lives only in `.env.local` (git-ignored) and is never sent to the browser. Make the AI provider swappable behind one module (`lib/ai.ts`, selected by an `AI_PROVIDER` env var). During development the default provider for AI translations is the **Gemini API free tier** (`GEMINI_API_KEY`); keep an Anthropic adapter (`ANTHROPIC_API_KEY`) or others pluggable without touching calling code.
- **Scripture text is stored locally in the project as static data**, never generated by AI. Use per-chapter JSON files (e.g., `data/texts/<work>/<version>/<book>/<chapter>.json`) plus a catalog file describing the library tree, so pages load fast and only fetch what is displayed.
- Highlights, bookmarks and notes: stored on the device (IndexedDB via a small wrapper) for now, behind a storage interface so it can later be swapped for user accounts + cloud sync (planned: Supabase auth/DB, Stripe payments — not in this build).
- Initialize git and commit at the end of each phase.
- Later deployment target: Vercel with the custom domain **snoopwiggy.com**. Keep it compatible. Source code is hosted on GitHub.

## Copyright rules (critical — this is a commercial product)

- Use **public-domain or commercially-permitted licenses only** (public domain, CC0, CC-BY, or explicit permission). **No CC-BY-NC / non-commercial texts.** No NIV, ESV, NLT, NKJV, RVR 1960, NEG 1979, Sefaria's Steinsaltz Talmud, etc.
- If the version I name is copyrighted, find the public-domain equivalent.
- Every version in the catalog must have: name, year, translator, license, and source URL. Create `LICENSES.md` listing all of them, with any required attribution shown in the app.
- Design the version system so licensed versions (NIV, ESV, RVR 1960, etc.) can be added later with a "licensed" flag. Do not add any now.
- Verify each license yourself before importing; if unsure, flag it to me instead of importing.

## Study features

- Tap/click a verse → action menu: Highlight (several colors), Bookmark, Add note, Copy, Ask in….
- "My Study" panel: list of bookmarks, highlights and notes; tap to jump to the verse.
- **Ask in… (current, free):** each verse has an "Ask in…" button. The user types an optional question, picks Gemini, ChatGPT or Claude, and the app builds a prompt (verse reference + the text of every currently visible translation/column + the user's question + a short instruction to answer scholarly and neutrally), copies it to the clipboard, and opens the chosen service in a new window. Pre-fill the prompt via URL where the service supports it (e.g., ChatGPT `https://chatgpt.com/?q=…`, Claude `https://claude.ai/new?q=…`); where it doesn't (Gemini), open the site and show a "Prompt copied — paste it in" toast. Keep URL templates in one config so they can be updated if a service changes. No AI API cost to us.
- **Built-in Ask AI panel (future paid tier, behind feature flag `NEXT_PUBLIC_FEATURE_ASK_AI_PANEL`, off by default):** opens a side panel (bottom sheet on phone) with the verse and its translations pre-loaded as context. Answers should be scholarly and neutral across traditions, explain translation differences between the columns when asked, and say when something is a matter of interpretation.
- Phase 4 extras carried over from the prototype: word thesaurus popup (translation, synonyms) and CEFR vocabulary-level annotations for language learners.
